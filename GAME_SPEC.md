# ONE MORE RUN

## 1. Назначение проекта

Создать небольшую HTML5-гиперказуальную игру для публикации на платформе Yandex Games.

Цель проекта:

1. Создать законченную игру, а не технический прототип.
2. Сделать игру достаточно интересной для повторных коротких сессий.
3. Подготовить игру к монетизации через Yandex Games SDK.
4. Получить первый реальный пользовательский трафик и протестировать возможность получения дохода.
5. Использовать проект как первый серьёзный учебный проект разработчика.
6. Код должен оставаться понятным начинающему разработчику.

Проект должен быть достаточно маленьким, чтобы один начинающий разработчик при помощи AI мог довести его до публикации.

---

# 2. Главный принцип проекта

Игра должна быть простой технически, но не выглядеть простой или дешёвой.

Нельзя создавать ощущение AI-generated template.

Запрещено использовать:

- смайлики в интерфейсе;
- случайные эмодзи вместо иконок;
- чрезмерные градиенты;
- случайные неоновые цвета;
- декоративные элементы без функционального смысла;
- чрезмерное количество UI-элементов;
- бессмысленные названия кнопок;
- типичный "AI game" стиль;
- случайно сгенерированные игровые механики;
- перегруженный интерфейс;
- фальшивые рейтинги;
- фальшивые отзывы;
- фальшивые достижения.

Визуальный стиль должен быть минималистичным, цельным и намеренным.

Все визуальные решения должны иметь объяснение.

Основная платформа:

Yandex Games.

Игра должна поддерживать:

- desktop;

Основная ориентация:

portrait для мобильных устройств.

На desktop игровое поле должно сохранять правильные пропорции.

# 5. Основная игровая идея

Игрок управляет объектом, движущимся по постоянно изменяющейся трассе.

Перед игроком появляются участки трассы с различными вариантами прохождения.

Игрок должен выбирать безопасный или рискованный путь.

Безопасный путь:

- легче пройти;
- даёт обычное количество очков.

Рискованный путь:

- сложнее пройти;
- даёт больше очков;
- может давать временный множитель.

Главная эмоция игры:

"Я почти побил свой рекорд. Ещё одна попытка."

---

# 6. Продолжительность игровой сессии

Одна игровая попытка должна занимать примерно:

30–120 секунд.

Первые секунды должны быть простыми.

Сложность постепенно увеличивается.

Игра не должна становиться нечестной.

Каждое столкновение должно происходить по понятной причине.

---

# 7. Управляемый объект

Игрок управляет одним объектом.

В первой версии использовать простую геометрическую форму или минималистичный визуальный объект.

Не использовать персонажа с лицом или мультяшным дизайном.

Объект должен иметь:

- понятный силуэт;
- небольшую анимацию движения;
- визуальную обратную связь при ускорении;
- визуальную обратную связь при столкновении.

---

# 8. Управление

## Desktop

Поддерживать:

- ArrowLeft;
- ArrowRight;
- A;
- D.

Также допускается управление мышью.

## Mobile

Поддерживать touch input.

Управление должно быть:

- мгновенным;
- предсказуемым;
- достаточно чувствительным;
- удобным одной рукой.

Не использовать виртуальный joystick без необходимости.

---

# 9. Игровое поле

Игровое поле должно занимать большую часть экрана.

UI не должен закрывать игровую область.

На игровом поле отображаются:

- игрок;
- трасса;
- препятствия;
- бонусы;
- необходимые игровые эффекты.

Игровое поле должно масштабироваться под размер окна.

---

# 10. Генерация трассы

Трасса должна генерироваться процедурно.

Это означает, что заранее не требуется создавать сотни уровней вручную.

Генератор должен создавать последовательность игровых сегментов.

Каждый сегмент может иметь:

1. обычный проход;
2. два прохода;
3. рискованный проход;
4. бонусный проход;
5. участок повышенной сложности.

Генератор обязан гарантировать возможность прохождения.

Нельзя создавать невозможные комбинации препятствий.

---

# 11. Сложность

Сложность увеличивается постепенно.

Увеличиваться могут:

- скорость движения;
- частота появления препятствий;
- количество вариантов;
- сложность расположения;
- количество рискованных участков.

Изменение сложности должно быть плавным.

Нельзя резко увеличивать сложность без причины.

---

# 12. Очки

Игрок получает очки за прохождение дистанции.

Дополнительные очки можно получать за:

- рискованный проход;
- серию успешных действий;
- бонусы;
- высокий multiplier.

На экране постоянно отображается текущий score.

---

# 13. Комбо

Если игрок несколько раз подряд успешно проходит рискованные участки, multiplier увеличивается.

Например:

1x  
2x  
3x  
4x

После ошибки multiplier уменьшается или сбрасывается.

Multiplier должен быть понятен визуально.

Не использовать чрезмерные анимации.

---

# 14. Рекорд

Игра должна хранить:

- текущий score;
- best score.

Best score сохраняется через localStorage.

После окончания игры игрок видит:

CURRENT SCORE

BEST SCORE

---

# 15. Главное меню

Главное меню должно быть минималистичным.

Содержимое:

Название игры.

Кнопка:

PLAY

Дополнительные кнопки:

LEADERBOARD

SETTINGS

LOGIN

Не показывать все кнопки одновременно, если это ухудшает интерфейс.

---

# 16. Экран окончания игры

После столкновения:

GAME OVER

CURRENT SCORE

BEST SCORE

Основная кнопка:

PLAY AGAIN

Дополнительная кнопка:

CONTINUE

Под кнопкой или непосредственно внутри неё должно быть ясно указано, что для продолжения пользователь посмотрит рекламу.

Например:

WATCH AD TO CONTINUE

Не использовать формулировки, которые скрывают факт рекламы.

---

# 17. Rewarded advertisement

Rewarded advertisement должна быть добровольной.

После проигрыша игрок может продолжить текущую попытку.

Reward:

- восстановление игры;
- небольшой период защиты;
- удаление ближайших опасных объектов.

Reward не должен полностью заменять игровой процесс.

Нельзя выдавать награду до подтверждения Yandex SDK о получении reward.

Если реклама не загрузилась:

- игра не должна ломаться;
- пользователь должен иметь возможность начать новую игру.

---

# 18. Fullscreen advertisement

Fullscreen advertisement можно показывать после завершения игровой сессии.

Не показывать fullscreen advertisement:

- во время активного gameplay;
- непосредственно во время управления;
- неожиданно после случайного нажатия;
- поверх игрового процесса.

Перед рекламой игра должна быть остановлена.

После рекламы игра должна корректно возобновляться.

---

# 19. Yandex Games SDK

Вся интеграция с Yandex Games SDK должна находиться в отдельном модуле.

Создать:

src/services/yandex.js

Игровая логика не должна напрямую зависеть от глобального объекта SDK.

Создать безопасную абстракцию.

Например:

YandexService.init()

YandexService.showInterstitial()

YandexService.showRewarded()

YandexService.login()

YandexService.submitScore()

YandexService.pause()

YandexService.resume()

Если SDK недоступен во время локальной разработки, игра должна продолжать работать.

Ошибки SDK не должны приводить к падению игры.

---

# 20. SDK initialization

После загрузки Yandex Games SDK выполнить:

YaGames.init()

После того как игра полностью готова для взаимодействия:

LoadingAPI.ready()

Не вызывать ready раньше времени.

---

# 21. Gameplay API

Использовать Gameplay API.

При начале активной игры:

GameplayAPI.start()

При:

- game over;
- открытии меню;
- показе рекламы;
- паузе;

вызывать:

GameplayAPI.stop()

---

# 22. Авторизация

Игрок должен иметь возможность играть без авторизации.

Авторизация не должна запускаться автоматически при загрузке.

Авторизация запускается только после сознательного действия пользователя.

Перед авторизацией необходимо объяснить пользу.

Например:

LOGIN TO SAVE YOUR RECORD

После авторизации:

- получить player;
- проверить isAuthorized();
- сохранить доступные данные;
- использовать аккаунт для leaderboard.

Если пользователь отказался:

игра продолжает работать.

---

# 23. Leaderboard

Использовать Yandex Games leaderboard.

Техническое имя:

bestScore

После окончания игры:

если пользователь авторизован и новый результат лучше предыдущего результата:

отправить score в leaderboard.

Не отправлять бессмысленные промежуточные значения.

Ошибки leaderboard не должны ломать игру.

---

# 24. Локальные сохранения

Создать отдельный модуль:

src/services/storage.js

Хранить:

- bestScore;
- soundEnabled;
- другие безопасные локальные настройки.

Использовать localStorage.

Код хранения не должен находиться внутри game.js.

---

# 25. Звук

В игре должна быть возможность полностью отключить звук.

Хранить состояние:

soundEnabled

Если пользователь выключил звук:

- музыка отключается;
- эффекты отключаются.

При потере фокуса браузера звук должен прекращаться.

Во время рекламы:

- игровой звук останавливается;
- игра ставится на паузу.

---

# 26. Визуальный стиль

Визуальный стиль должен выглядеть как небольшая коммерческая инди-игра.

Основные требования:

- ограниченная палитра;
- максимум несколько основных цветов;
- хороший контраст;
- чёткая типографика;
- отсутствие декоративного мусора;
- аккуратные переходы;
- небольшие анимации;
- понятная иерархия UI.

Не использовать emoji.

Не использовать стандартные браузерные кнопки без стилизации.

Не использовать случайные бесплатные ассеты без единого художественного стиля.

---

# 27. UI

UI должен быть компактным.

Во время gameplay:

верхняя часть:

SCORE

BEST

MULTIPLIER

Не закрывать ими игровой объект.

В меню использовать простую иерархию.

Основная кнопка должна быть визуально главной.

Вторичные функции не должны конкурировать с PLAY.

---

# 28. Анимации

Использовать небольшие анимации:

- появление объектов;
- движение;
- успешный рискованный проход;
- изменение multiplier;
- столкновение;
- переход между состояниями.

Анимации не должны замедлять игру.

Не использовать чрезмерные particles.

---

# 29. Производительность

Игра должна работать плавно на слабых мобильных устройствах.

Не создавать тысячи DOM-элементов.

Игровые объекты должны отрисовываться через Canvas.

Удалять объекты, которые покинули игровую область.

Не создавать бесконечные timers.

Использовать requestAnimationFrame для игрового цикла.

---

# 30. Обработка изменения размера

Игра должна корректно работать при:

- изменении размера окна;
- повороте мобильного устройства;
- сворачивании браузера;
- возвращении во вкладку.

Игровой state не должен сбрасываться при обычном resize.

---

# 31. Пауза

При потере фокуса:

- gameplay останавливается;
- звук останавливается.

После возврата:

- игра не должна автоматически продолжаться, если это создаёт риск случайной смерти;
- предпочтительно показать состояние PAUSED.

Игрок должен осознанно продолжить игру.

---

# 32. Ошибки

Игра никогда не должна показывать пользователю:

- stack trace;
- JavaScript error;
- undefined;
- null;
- технические сообщения;
- ошибки SDK.

Ошибки записываются в console для разработчика.

Пользователю показывается понятное состояние.

---

# 33. Локализация

Первая версия должна поддерживать:

- Russian;
- English.

Не использовать hardcoded UI strings непосредственно в игровой логике.

Создать:

src/localization/

Например:

ru.json

en.json

Язык должен определяться через окружение Yandex Games SDK.

Если определить язык невозможно:

использовать English или Russian fallback.

---

# 34. Монетизация

Основной способ монетизации:

Yandex Games advertising.

Использовать:

- fullscreen ads;
- rewarded ads.

Не использовать сторонние рекламные сети.

Не использовать внешние рекламные скрипты.

Не показывать рекламу во время активного gameplay.

---

# 35. Подход к монетизации

Не пытаться максимизировать количество рекламных показов.

Приоритет:

1. удержание игрока;
2. качество игры;
3. повторные сессии;
4. только после этого рекламная монетизация.

Игрок должен хотеть сыграть ещё одну попытку даже без рекламы.

Rewarded advertising должна быть добровольной.

---

# 36. Повторные игровые сессии

Игра должна создавать желание повторить попытку.

Для этого использовать:

- best score;
- multiplier;
- постепенное увеличение сложности;
- рискованные участки;
- leaderboard.

Не использовать искусственные таймеры, заставляющие игрока ждать.

---

# 37. Ежедневная задача

Не добавлять daily rewards в первой версии.

Сначала сделать стабильное основное gameplay.

После публикации и получения статистики можно рассмотреть:

- daily challenge;
- daily score;
- специальные режимы.

---

# 38. Anti-frustration

Игрок должен понимать причину проигрыша.

После столкновения должна быть визуальная обратная связь.

Не должно быть:

- невидимых препятствий;
- случайных смертей;
- невозможных комбинаций;
- внезапного ускорения;
- управления с задержкой.

---

# 39. Контент

Не использовать защищённые авторским правом:

- персонажей;
- логотипы;
- музыку;
- изображения;
- названия;
- бренды.

Все созданные визуальные элементы должны быть оригинальными или иметь разрешённую лицензию.

# 41. Обязательное правило для AI

Перед изменением архитектуры Gemini должен объяснить:

1. Что он хочет изменить.
2. Зачем это нужно.
3. Какие файлы будут затронуты.
4. Какие альтернативы существуют.
5. Почему выбран именно этот вариант.

Если изменение маленькое и очевидное, достаточно краткого объяснения.

---

# 42. Обязательное правило обучения

После каждого значимого этапа Gemini должен объяснять мне:

### Что сделано

Краткий список.

### Как это работает

Простое объяснение без сложной терминологии.

### Что мне нужно понять

2–5 основных вещей.

### Как проверить

Конкретные действия.

### Что дальше

Следующий этап разработки.

Не писать огромные лекции.

---

# 43. Правило против AI-slop

Не генерировать код только ради увеличения количества кода.

Не добавлять функции без необходимости.

Не добавлять:

- achievements;
- inventory;
- skins;
- coins;
- shop;
- quests;
- battle pass;
- daily rewards;
- pets;
- character customization;

до тех пор, пока базовая игра не доказала, что она интересна.

Сначала сделать одну хорошую механику.

---

После каждого крупного изменения:

1. проверить JavaScript;
2. проверить консоль;
3. проверить основные игровые состояния;
4. проверить resize;
5. проверить mobile controls;
6. проверить pause;
7. проверить restart;
8. проверить localStorage.

Не считать задачу завершённой только потому, что код написан.

# 49. Рекламные требования

Все рекламные показы выполняются только через Yandex Games SDK.

Реклама:

- не должна неожиданно прерывать gameplay;
- не должна мешать управлению;
- должна показываться в логических паузах;
- должна ставить игру и звук на паузу.

Rewarded-реклама должна быть добровольной.

Кнопка rewarded-рекламы должна ясно показывать:

1. что пользователь смотрит рекламу;
2. какую награду он получит.

Не подключать неизвестные внешние скрипты.

Минимизировать внешние зависимости.
