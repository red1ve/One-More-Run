# Полный план доработки «One More Run» (передача в новую сессию)

Этот файл читает новая (облачная) сессия Claude Opus. Пользователь: не программист, первая игра, общается по-русски. Все объяснения давать по-русски, простыми словами (правила в `CLAUDE.md`, «Teaching mode»).

Референс: `docs/reference/reference.webp`. Журнал работы: `docs/handoff/PROGRESS.md` (обновлять после каждого шага).

Сессия облачная: результат живёт только в git. Работать в рабочей ветке (например `rework/visual-match`), маленькими коммитами, Pull Request на каждую фазу. В `main` напрямую не писать. Слияние делает пользователь.

## Наблюдения по референсу (для `reference-checklist.md`)

Проверить по самой картинке и уточнить.
- Портретный кадр. Дорога идёт почти до верха кадра, небо это узкая голубая полоска с облаками и деревьями, на дальнем конце деревянная арка с розами.

- HUD: капсулы (счёт с лапой и BEST, монеты, серия, множитель), округлый жирный шрифт. Иконка огня заменена своей.

## Что НЕ трогать (жёсткие правила)

- Физика, хитбоксы, коллизии, скорость, достижимость проходов, награды. Меняется только внешний вид.
- Спрайты Loaf (`assets/characters/*`) как продакшн-ассеты. Не перерисовывать, кроме нового спрайта для Game Over.
- Палитра и стиль `docs/visual-bible.md` (SkyPaper #F3E4C7, GardenSky #D5E5EA, FloorSand #E2C992, HedgeSage #6F9A5E, PlanterWood #C4A06A, CoinAmber #E8B84A, InkBrown #4A3428, ShadowDust #C4A97A и т.д.). Не более 6 основных цветов на экран, без эмодзи, единый плоский cel-shaded стиль, не смешивать живописный фон с плоской графикой.
- Два разных механизма: геймплейные границы (`src/game/Corridor.js`) и визуальная проекция (`src/rendering/VisualProjector.js`). Коллизии и игрок используют НЕпроецированные координаты. Не смешивать.
- Яндекс-код только в `src/services/YandexService.js`. Игра обязана работать без SDK (404 на `/sdk.js` локально ожидаем).
- Никаких новых зависимостей и больших рефакторингов без согласия пользователя. Стек фиксирован.

## Стартовое состояние

- Стек: HTML5 Canvas 2D, JS ES-модули, Vite (порт 3000), Yandex SDK изолирован. Шрифт Fredoka через `@fontsource/fredoka`.
- Игра играбельна: движение, препятствия, коллизии, счёт, множитель, монеты, SAFE/RISK-выборы, ускорение, Game Over, звук, паттерны трека (OFFSET/FUNNEL/OFFSET_GATE/DOUBLE_GATE).
- Перспектива: одна формула `u = D/(D+d)` в `VisualProjector.js` (`FALLOFF_DISTANCE` 460). От `u` зависят экранный Y, масштаб (0.88→1), ширина дороги (`FAR_ROAD_WIDTH` 200 → около 348 у кота), прозрачность и контраст. Горизонт `VISUAL.SKY_BAND` = 232.
- Появление объектов: `horizonOcclusion` даёт плавное проявление (альфа), тестовая обвязка `?reveal=A..E` в dev-режиме.
- HUD в стиле референса. Арка-ориентир на горизонте (`drawHorizonLandmark` в `src/rendering/GardenArt.js`).
- Текстура дорожки без полос. Планировщик препятствий: `STANDING_PLANTER` использует `planter-04/-06/-08` (цветущие), `planter-07` это шпалера.
- `npm run check` (phase4/7/8/9, около 121 проверки) зелёный. Известная нестабильная проверка «Choice fork position can vary…» не связана с визуалом.
- Обнаруженные ограничения: небо/дальний слой это запечённый PNG `distant-garden-horizon.png` (тёплый рассвет) вместо чистого голубого неба; Fredoka без кириллицы; `ru.json`/`en.json` заглушки по 5 строк.

### Фаза 1. Совпадение мира с референсом
Идти по `reference-checklist.md`, по одному элементу, после каждого делать кадр и сравнение с референсом. По элементу не более 3 итераций, затем показать пользователю.
1. Форма дороги и кустов. Самая широкая часть у кота, сужение к арке. Подобрать `FAR_ROAD_WIDTH`, `FALLOFF_DISTANCE`, диапазон масштаба, горизонт `SKY_BAND`; ширина кустов из `hedgeBorderWidth` должна следовать перспективе.
2. Живая изгородь: цветы, ровная стрижка, низкий деревянный бордюр у основания.
3. Арка на горизонте: размер, лёгкая воздушная дымка, при необходимости отдельная арка в розах.
4. Препятствия: больше парных цветущих кашпо и деревянные ворота с цветком как на референсе. Геометрию столкновений не менять.
5. Боковой декор: камни, заборчики, деревья, цветущие кусты за изгородью.
6. Небо и дальний слой: плоское голубое небо с облаками и ряд холмов/деревьев вместо запечённого PNG (арт-задача, выбор источника графики согласовать с пользователем).
7. Итоговая сверка цвета и контраста, тень кота.

### Фаза 2. Плавность и «ощущение»
- Статичные кадры не доказывают плавность. Сделать скриптовый тест движения: детерминированный запуск (seed), запись координат каждого препятствия по кадрам, проверка «нет скачков по X больше N пикселей за кадр» и «размер меняется монотонно». Использовать `scripts/depth-probe.mjs` и `?reveal=A..E`.
- Проверить, что объекты не выплывают из-за кустов сбоку, а растут на своём месте (главная претензия пользователя).
- FPS на слабом устройстве (замедление CPU в Playwright), отсутствие лишних аллокаций.

## C. Инструменты (облачная сессия)

Облачная Linux-машина без рабочего стола пользователя. Главный инструмент один, запасной есть.

| Инструмент | Нужен? | Как |
|---|---|---|
| Playwright MCP | ДА | Прописан в `.mcp.json` (`npx -y @playwright/mcp@latest`). Обязательно проверить, что сервер поднялся (вызвать любой его инструмент). Браузер: `npx playwright install --with-deps chromium` |
| Запасной путь без MCP | Если MCP или загрузка браузера не сработали | Добавить в `devDependencies` пакет `playwright` (спросить разрешение у пользователя) и скрипт `scripts/capture.mjs`: headless-запуск, окно 600×1067, `page.evaluate(() => canvas.toDataURL())` → PNG, серия кадров, лог консоли. Запускать через Bash |
| Встроенный браузер приложения (`preview_start`) | НЕТ | В облаке недоступен |
| GitHub | git и `gh` в самой сессии, отдельный MCP не нужен | Репозиторий подключён к аккаунту пользователя |
| image-MCP (OpenAI) | НЕТ | Локальный путь `C:/Users/...` в облаке не существует; ключи в облако не вводить. Графику рисует Opus в SVG или пользователь кладёт готовые файлы в `assets/` |
| Context7 / docs-MCP | Необязательно | Для Яндекса лучше WebFetch на официальную документацию |

Настройка облачной среды (делает пользователь один раз, по документации Claude Code): в приложении и на claude.ai/code кнопка с названием среды (по умолчанию «Default») в строке над полем ввода → в разделе Cloud навести на среду и нажать значок шестерёнки (или «Add cloud environment»). В диалоге поля: Name, Network access, Environment variables, Setup script.
- Setup script (Bash, запускается от root на Ubuntu 24.04 перед стартом сессии, должен завершаться кодом 0 и укладываться примерно в 5 минут, результат кэшируется):
  ```bash
  #!/bin/bash
  npm ci || true
  npx playwright install --with-deps chromium || true
  ```
- Network access: уровень «Trusted» пускает npm, GitHub и apt (Ubuntu), но не пускает загрузку браузера Playwright. Выбрать **Custom**, оставить домены по умолчанию и добавить в «Allowed domains»: `cdn.playwright.dev`, `playwright.download.prss.microsoft.com`, `playwright.azureedge.net`. Запасной вариант: **Full** (проект не содержит секретов).
- `.mcp.json`, `.claude/agents/` и `CLAUDE.md` из репозитория облачная сессия подхватывает сама (для сессии с одним репозиторием).

Как получать кадр (проверено на этом проекте): `document.getElementById('game-canvas').toDataURL('image/png')` → сохранить → `node scripts/_decode-canvas.mjs <файл> <out.png>` → прочитать PNG. Окно 600×1067. В Playwright можно снимать сам элемент canvas (`locator.screenshot`). Кадры для пользователя коммитить в `docs/reference/progress/<фаза>/`.

Заметки по опыту: скриншот окна во встроенном браузере ненадёжен; эмуляция «mobile» ломала масштаб, лучше явный размер 600×1067; тест «Choice fork position can vary…» иногда нестабилен; ошибка загрузки `/sdk.js` локально ожидаема.
